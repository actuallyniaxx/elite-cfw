# elite-cfw

Custom-firmware patcher for the **Xiaomi Electric Scooter Elite** controller
(Nations **N32G430** MCU, "Leqi" / `mi5elite` family).

It takes your *stock* controller firmware and produces a patched image that adds
a **speed toggle gesture** and a **conditional zero-start**, with no extra
hardware. Single Python file, standard library only.

> ⚠️ **Experimental. Use at your own risk.** This modifies how your scooter's
> motor controller behaves. Keep a backup of your stock firmware. Deslimiting a
> scooter may be illegal to ride on public roads where you live — that's on you.
> Not affiliated with or endorsed by Xiaomi.

---

## What it does

| Feature | Behaviour |
|---|---|
| **Speed toggle** | Hold **brake + throttle together** (one firm tap: throttle ≳80 %, brake ≳60 %, at the same time) to toggle the speed cap between **25 km/h** and **40 km/h**. Edge-detected, so one press = one toggle. |
| **Conditional zero-start** | While **unlocked (40)**, kick-start is disabled — the motor drives from a standstill. While **locked (25)**, the stock kick-start is kept (you push to start). |
| **Region cap** | Raised to 50 km/h so the 40 km/h state isn't actively braked by the region limiter. |

The real top speed is motor-limited (~28–30 km/h on a stock 36 V Elite motor); the
40 km/h cap just stops the firmware from capping you below what the motor can do.

### How the gesture "remembers" state

The unlock state lives in controller RAM and behaves like a **switch**: it stays
where you leave it, even across power cycles. On this controller the power button
does **not** cold-clear the RAM, so there is no reliable "always start at 25 on
power-on" — you toggle it yourself when you want it. (If you need it locked, just
do the gesture to lock it.)

## Supported firmware

This patcher targets **one specific stock version** and refuses anything else
(it checks the SHA-256 of the decrypted firmware body before touching a byte):

```
Xiaomi Scooter Elite — controller MCU, EU, v0.1.2.0
SHA-256 (decrypted body): 017d2e67515919d52962c26ac70b790977c3acd391b2a31444861ec0814c503c
```

If your stock firmware has a different hash, **do not force it** — the offsets
won't match and you'd brick the controller. Open an issue with your version.

## Usage

```bash
python3 elite_cfw.py mcu_xiaomi.scooter.elite.bin -o elite_cfw.bin
```

- Input: your **stock** controller firmware (the `mcu_*.bin`, full image with the
  `EU1` header — not the BLE/dashboard `upd_*.bin`).
- Output: `elite_cfw.bin`, ready to flash.

The tool verifies the stock version, applies the patches, recomputes the CRC and
re-encrypts the image. No dependencies beyond Python 3.

---

## Flashing

Flash `elite_cfw.bin` to the **controller** over **UART** (e.g. with
[`bw-flasher`](https://github.com/ScooterTeam/bw-flasher), or any Leqi/N32 UART
flasher). You need a USB-UART adapter (3.3 V) on the controller's dashboard
connector: **GND, controller-RX ← adapter-TX, controller-TX → adapter-RX**, with
the battery connected.

UART flashing never touches the bootloader, so a bad flash is always recoverable:
just re-flash your **stock** backup the same way.

> **Keep your stock `mcu_*.bin`.** That's your rescue image.

## Known limitations

- **No auto-lock at power-on** — the RAM persists across power cycles on this
  controller (see above). The gesture is a toggle, not a per-boot reset.
- **The 30 km/h warning beep is not changed** — it is generated by the
  dashboard/BLE board, not the controller, so it lives in a different firmware
  (`upd_*.bin`) that this patcher does not touch.
- **Field weakening is not included** — top speed stays motor-limited.

## How it works (for the curious)

The firmware is a full image: `0x80`-byte header + XOR-`0xAA`-encrypted body +
CRC-16 (poly `0x8005`, bit-reversed) stored big-endian at the body size from the
`EU1` header field, computed over the **encrypted** body `[0x40 : size-2]`.

The patches (all verified against expected stock bytes before applying):

1. **Parser hijack** @ `0x08003C18` — intercepts where the controller reads the
   dashboard speed-limit byte, and branches into an injected routine.
2. **Injected blocks** in free flash @ `0x0800B518`:
   - *Toggle*: reads the raw dashboard throttle/brake bytes (`0x20000535` /
     `0x20000536`), edge-detects the brake+throttle gesture, flips an unlock flag
     in free RAM (`0x20003F00`), and forces the speed limit to 40 km/h when
     unlocked (otherwise passes the stock dashboard value through).
   - *Kick-start helper*: used by the hook below.
3. **Kick-start hook** @ `0x08008C14` — when unlocked, forces the motor-start
   speed metric high so both kick-start gates pass → zero-start; otherwise stock.
4. **Region cap** @ `0x08004058` — `35.0 → 50.0 km/h`.

Reading the dashboard bytes *raw* sidesteps the firmware's brake↔throttle
interlock (which zeroes the processed throttle when braking), so the two-finger
gesture is detectable even though you're "braking and accelerating" at once.
